## 1. AI Integration Guide — read this first

You are an AI agent working on this repository. Before you touch code:

1. **Read this file.** Find the context(s) relevant to your task in the Registry (§3) using the Category column or `node ai-driven-project/cli/context.mjs search <keyword>`.
2. **Open those context files** and follow their `Dependencies` to pull in related context. Each file is self-describing (format in §4).
3. **Do the work** against the real code (the contexts point to exact `file:line` references — verify they still hold; code is the source of truth, contexts are the map).
4. **When you finish, you MUST update the context system** (this is mandatory, not optional):
   - If you changed code that a context describes → update that context's **Key Information**, **Code References**, bump **Last Updated** (ISO-8601), and add a **Change Log** entry.
   - If you added a new subsystem/feature → create a new context file (§4), give it the next free ID in its category, and wire up **Dependencies**/**Related Contexts**.
   - Re-run the indexer: `node ai-driven-project/cli/context.mjs index` (regenerates §3 + §6).
   - Validate: `node ai-driven-project/cli/context.mjs validate && node ai-driven-project/cli/context.mjs check`.
   - Commit using Conventional Commits with scope `context` (see INFRA-003), e.g. `docs(context): update FEAT-003 after carousel change`.

> **Contract**: leaving the codebase changed but the context stale is an incomplete task. The map must match the territory.

## 4. Context File Format Standard

Every context file MUST contain, in order:

1. A fenced **`json ai-meta`** block (machine-readable metadata for AI consumption):
   ````
   ```json ai-meta
   { "id": "FEAT-003", "name": "...", "category": "features",
     "lang": ["pt-BR"], "tags": ["..."], "dependencies": ["CORE-003"],
     "stack": "next-app-router-website" }
   ```
   ````
2. A human-readable header:
   ```markdown
   # Context: [NAME]
   **ID**: [CORE|FEAT|INFRA|UTIL]-NNN
   **Category**: [core|features|infrastructure|utilities]   # must equal the folder
   **Last Updated**: [ISO-8601 timestamp]
   **Dependencies**: [comma-separated IDs, or "none"]
   **Description**: [≤ 100 chars, used verbatim in the Registry]
   ```
3. These sections (all required), in order:
   - `## Summary` — what this context covers
   - `## Key Information` — the substance, in clear subsections
   - `## Code References` — `path:line` pointers into the repo
   - `## Related Contexts` — markdown links to dependent/related files
   - `## Change Log` — newest-first, timestamped entries

**Consistency rules** (enforced by `validate`): `ai-meta.id`/`category` must match the header; the header `Category` must match the directory; IDs must be unique and match `PREFIX-NNN`; description ≤ 100 chars.

## 5. Usage Rules, Update Protocols & Control Mechanisms

### Creating a context
1. Choose the category folder → file name in `kebab-case.md`.
2. Assign the **next free ID** in that category (check the Registry; `check` flags duplicates).
3. Fill the format from §4. Keep it factual and tied to real `file:line` references.
4. Declare `Dependencies` both in `ai-meta` and the header.
5. `node cli/context.mjs validate` → `index` → `check`.

### Updating a context
- Edit content, bump **Last Updated**, prepend a **Change Log** entry (`<ISO-ts> — <what & why>`).
- Re-run `index` so the Registry reflects the new date/description.

### Update protocol after a code change (mandatory)
`change code → update affected context(s) → index → validate → check → commit docs(context): …`

### Control mechanisms (run via the CLI)
| Mechanism | Command | What it catches |
| --- | --- | --- |
| Format validation | `validate` | Missing fields/sections, bad ID, JSON/markdown drift, over-long description |
| Duplicate prevention | `check` | Two files sharing an ID |
| Dependency tracking | `check` | `Dependencies` pointing at non-existent IDs |
| Orphan detection | `check` | Contexts referenced by no other context (review whether intended) |
| Link integrity | `check` | Dead relative links in "Related Contexts" |
| Auto-indexing | `index` | Registry/JSON drift vs. files on disk |
| Search | `search <term>` | Locating a context by ID/name/tag/body |
